# SettingsExtension

Данный пример демонстрирует реализацию расширения Сервиса настроек, обеспечивающего хранение конфиденциальных значений (паролей, строк подключения и т.п.) во внешнем хранилище секретов, отдельно от основного хранилища Сервиса настроек.

В качестве хранилища секретов в примере используется [OpenBao](https://openbao.org/) — Open Source форк HashiCorp Vault, полностью совместимый с ним по API.

## Описание примера

Пример включает два проекта:

- **OpenBao** — реализация интерфейса `ISecretStorageConnector` (`OpenBaoSecretStorageConnector`) для хранилища OpenBao/HashiCorp Vault с движком секретов KV v2. Поддерживает аутентификацию по токену.
- **OpenBao.Tests** — интеграционные NUnit-тесты коннектора, проверяющие подключение к серверу OpenBao и операции записи/чтения/удаления секретов.

## Настройка среды

Пример рассчитан на версию Сервиса настроек с поддержкой подключаемых хранилищ секретов (интерфейс `ISecretStorageConnector`).

**Перечень необходимых инструментов:**
* [Visual Studio 2022](https://www.visualstudio.com) с .NET SDK 8.0+
* Доступный сервер [OpenBao](https://openbao.org/) (или совместимый по API HashiCorp Vault) с включённым движком секретов версии KV v2

## Сборка проекта

1. Откройте решение `/Samples.sln`.
2. Соберите проект Others > SettingsExtension > OpenBao.

В результате в папке `Others\SettingsExtension\OpenBao\bin\Debug\net8.0` (или `Release`) появятся файлы `OpenBao.dll` и `VaultSharp.dll` (зависимость коннектора, используемая для обращений к OpenBao).

## Проверка коннектора автономно (без Сервиса настроек)

Перед интеграцией с Сервисом настроек можно проверить работу коннектора отдельно, с помощью интеграционных тестов проекта OpenBao.Tests.

1. Получите адрес тестового сервера OpenBao и токен с правами на чтение/запись/удаление секретов в используемом движке KV v2.
2. Запустите тесты одним из способов:
   - задав переменные окружения `Test__OpenBao__Url` и `Test__OpenBao__Token`;
   - либо создав в папке `OpenBao.Tests` файл `local.runsettings` (добавлен в `.gitignore`, в репозиторий не попадает) со следующим содержимым:

     ```xml
     <?xml version="1.0" encoding="utf-8"?>
     <RunSettings>
       <RunConfiguration>
         <EnvironmentVariables>
           <Test__OpenBao__Url>http://your-openbao-server:8200</Test__OpenBao__Url>
           <Test__OpenBao__Token>your-token-here</Test__OpenBao__Token>
         </EnvironmentVariables>
       </RunConfiguration>
     </RunSettings>
     ```

3. Выполните тесты из `OpenBao.Tests` — тесты должны пройти успешно.

Если переменные окружения не заданы, тесты автоматически пропускаются.

## Подключение коннектора к Сервису настроек

1. Скопируйте файлы `OpenBao.dll` и `VaultSharp.dll` в папку `/lib/docsvision/common` каждого компонента, которому нужен доступ к защищённым настройкам:
   - на сервере с установленной Консолью управления;
   - на сервере, где будет выполняться проверка получения настроек. В данном примере, нужно скопировать на сервер с компонентом Сервер Docsvision.

2. В конфигурационном файле Консоли управления (`appsettings.json`) в раздел `SettingsService` добавьте секцию `SecretStorage`:

   ```json
   "SettingsService": {
     "ConnectionString": "<адрес API Сервиса настроек>",
     "ApiKey": "<ключ доступа к Сервису настроек>",
     "SecretStorage": {
       "ConnectorType": "OpenBao.OpenBaoSecretStorageConnector, OpenBao",
       "Settings": {
         "Url": "http://your-openbao-server:8200",
         "Token": "<токен с правами на чтение/запись/удаление секретов>"
       }
     }
   }
   ```

   Необязательные параметры внутри `Settings`:
   - `MountPath` — название движка секретов (Secrets Engine) в OpenBao. По умолчанию `secret`.
   - `PathPrefix` — префикс, добавляемый ко всем путям секретов (удобно, если несколько окружений используют общее хранилище OpenBao).

3. В конфигурационном файле сервера Docsvision (и любого другого потребителя настроек, читающего защищённые значения через Сервис настроек) добавьте в раздел `Docsvision:SettingsService` точно такую же секцию `SecretStorage`.

4. Перезапустите Консоль управления.

## Проверка примера

В хранилище секретов сохраняются значения только тех настроек, которые специальным образом размечены на странице настроек компонента в Консоли управления. Один из таких параметров: пароль системного пользователя модуля «Платформа».

1. В Консоли управления откройте страницу настроек сервиса «Платформа» и задайте/измените значение пароля системного пользователя. Сохраните настройки.
2. Узнайте Id сервиса «Платформа» в Сервисе настроек — он виден в адресной строке браузера при открытии его страницы настроек в Консоли управления.
3. Убедитесь непосредственно в OpenBao (UI/CLI/API хранилища), что в движке секретов (`MountPath`, по умолчанию `secret`) появился секрет по пути `Configuration/<Id сервиса "Платформа">/SystemUserPassword` (с учётом `PathPrefix`, если он задан), содержащий заданный пароль в поле `value`.
4. Перезапустите сервер «Платформа» и убедитесь, что он успешно стартует, используя этот пароль, — значит, значение было корректно прочитано из OpenBao.
